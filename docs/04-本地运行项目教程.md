# VoFlow Platform 本地运行项目教程

本文档按当前仓库配置整理，适用于在本机启动 VoFlow Platform 的 Next.js Web 应用、PostgreSQL、Redis、MinIO 对象存储，并完成数据库初始化和访问验证。

## 1. 项目技术栈

- 前端/后端一体框架：Next.js 15 App Router
- UI 运行时：React 19
- 数据库：PostgreSQL
- ORM：Prisma
- 缓存/会话依赖：Redis
- 对象存储：MinIO
- 测试框架：Vitest

主要入口：

- Web 应用：首页 `http://localhost:3000`
- 登录页：`http://localhost:3000/login`
- 管理后台：`http://localhost:3000/dashboard`
- 健康检查：`http://localhost:3000/api/health`
- MinIO API：`http://localhost:9000`
- MinIO Console：`http://localhost:9001`

## 2. 前置要求

建议使用：

- Node.js 20 LTS 或 22 LTS
- npm
- PostgreSQL 16 或兼容版本
- Redis 7 或兼容版本
- MinIO
- 可选：`yt-dlp`，用于公开参考链接 metadata、字幕和授权后音频参考分析
- 可选：`ffmpeg`，用于音频提取后处理，以及后续视频/音频处理能力

如果使用 Docker Compose，只需要额外保证 Docker Desktop 已启动。

检查命令：

```bash
node -v
npm -v
docker --version
docker compose version
yt-dlp --version
ffmpeg -version
```

`yt-dlp` 和 `ffmpeg` 不是基础 Web 应用启动的必需项。未安装时，登录、项目、素材上传、任务列表等基础功能仍可运行；只有开启真实公开参考链接导入、并实际使用 metadata/字幕/音频提取路径时才需要它们。

## 4. 环境变量

项目通过 `.env` 读取本地运行配置。首次运行时复制示例文件：

```bash
cp .env.example .env
```

当前示例配置如下：

```bash
DATABASE_URL="postgresql://voflow:voflow123@localhost:5432/voflow?schema=public"
REDIS_URL="redis://localhost:6379"
MINIO_ENDPOINT="localhost"
MINIO_PORT="9000"
MINIO_ACCESS_KEY="voflow"
MINIO_SECRET_KEY="voflow123"
MINIO_BUCKET="voflow"

SESSION_SECRET="your-super-secret-session-key-change-in-production"

LLM_BASE_URL="http://localhost:8000"
LLM_MODEL="llama3.2"
TTS_BASE_URL="http://localhost:5000"
ASR_BASE_URL="http://localhost:6000"
AVATAR_BASE_URL="http://localhost:7000"
FFMPEG_WORKER="/usr/local/bin/ffmpeg"
GPU_MODE="auto"
QUEUE_REDIS_URL="redis://localhost:6379"

VOFLOW_REFERENCE_LINK_IMPORT_ENABLED="false"
VOFLOW_YTDLP_BIN="yt-dlp"
VOFLOW_YTDLP_TIMEOUT_MS="60000"
VOFLOW_REFERENCE_MAX_DURATION_MS="180000"
VOFLOW_REFERENCE_MAX_AUDIO_MB="50"
VOFLOW_REFERENCE_MAX_METADATA_BYTES="2097152"
VOFLOW_REFERENCE_MAX_SUBTITLE_BYTES="5242880"
VOFLOW_REFERENCE_ALLOW_AUDIO_EXTRACT="true"
VOFLOW_REFERENCE_ALLOW_FULL_VIDEO_DOWNLOAD="false"
VOFLOW_REFERENCE_ALLOWED_PLATFORMS="youtube,bilibili"
```

说明：

- `DATABASE_URL` 必须能连接 PostgreSQL，并且用户需要有创建/迁移表结构的权限。
- `REDIS_URL` 用于 Redis 连接。
- `MINIO_*` 用于素材上传、文件存储和 presigned URL 生成。
- `LLM_BASE_URL`、`TTS_BASE_URL`、`ASR_BASE_URL`、`AVATAR_BASE_URL` 是本地 AI 模型服务地址；这些服务离线时，基础 Web 应用仍可启动，但健康检查中对应模型服务会显示 `offline`。
- `FFMPEG_WORKER` 是本地 FFmpeg 可执行文件路径；缺失时本地模型监控会标记为 `misconfigured`。
- `GPU_MODE` 和 `QUEUE_REDIS_URL` 为后续 Worker 调度和资源监控预留配置。
- `VOFLOW_REFERENCE_LINK_IMPORT_ENABLED` 默认是 `false`。默认情况下，公开参考链接真实导入不调用 `yt-dlp`，页面保留上传视频/音频或粘贴文案 fallback。
- `VOFLOW_YTDLP_BIN` 是 `yt-dlp` 可执行文件路径；如果不在 `PATH` 中，改成绝对路径，例如 `/opt/homebrew/bin/yt-dlp`。
- `VOFLOW_REFERENCE_ALLOWED_PLATFORMS` 是真实 `yt-dlp` 导入 allowlist，默认只包含 `youtube,bilibili`。
- `VOFLOW_REFERENCE_ALLOW_AUDIO_EXTRACT` 控制授权后音频提取，默认允许；`VOFLOW_REFERENCE_ALLOW_FULL_VIDEO_DOWNLOAD` 默认必须保持 `false`，MVP 不提供完整视频下载、cookie/登录态导入、去水印或批量采集。
- `VOFLOW_REFERENCE_MAX_DURATION_MS`、`VOFLOW_REFERENCE_MAX_AUDIO_MB`、`VOFLOW_REFERENCE_MAX_METADATA_BYTES`、`VOFLOW_REFERENCE_MAX_SUBTITLE_BYTES` 分别限制参考链接最大时长、音频大小、metadata 输出和字幕大小。

启用真实公开参考链接导入的最小本地配置示例：

```bash
VOFLOW_REFERENCE_LINK_IMPORT_ENABLED="true"
VOFLOW_YTDLP_BIN="yt-dlp"
VOFLOW_REFERENCE_ALLOWED_PLATFORMS="youtube,bilibili"
VOFLOW_REFERENCE_ALLOW_AUDIO_EXTRACT="true"
VOFLOW_REFERENCE_ALLOW_FULL_VIDEO_DOWNLOAD="false"
```

国内平台口径：

- 抖音、快手、小红书、视频号、TikTok 等链接可以做平台识别和前端提示。
- 当前真实 `yt-dlp` 导入默认不承诺自动提取这些平台；不在 allowlist 或解析失败时，应提示上传视频/音频或粘贴文案继续。
- 不要通过 cookie、登录态、去水印工具或批量频道采集绕过平台限制；这些能力不在 VoFlow MVP 范围内。

## 5. 启动基础设施

本项目支持两种模式。二选一即可，不要同时让 Docker 和本机服务占用同一批端口。

### 模式 A：Docker Compose

适合没有本机 PostgreSQL/Redis/MinIO，且 Docker Desktop 正常可用的环境。

```bash
docker compose up -d
docker compose ps
```

Compose 会启动：

- PostgreSQL：`localhost:5432`
- Redis：`localhost:6379`
- MinIO API：`localhost:9000`
- MinIO Console：`localhost:9001`

`minio-init` 服务会自动创建私有 bucket：`voflow`。

如果端口已经被本机服务占用，先停止冲突服务，或改用模式 B。

Docker Compose 只启动 PostgreSQL、Redis 和 MinIO，不会在容器中运行 Next.js Web 应用，也不会自动安装 `yt-dlp` 或 `ffmpeg`。如果你在宿主机执行 `npm run dev`，就需要把 `yt-dlp`/`ffmpeg` 安装到宿主机，并确保 `.env` 中的 `VOFLOW_YTDLP_BIN` 和 `FFMPEG_WORKER` 指向宿主机可执行文件。

### 模式 B：Homebrew 本机服务

适合本机已经通过 Homebrew 运行 PostgreSQL/Redis 的环境。

检查端口：

```bash
lsof -nP -iTCP:5432 -sTCP:LISTEN
lsof -nP -iTCP:6379 -sTCP:LISTEN
lsof -nP -iTCP:9000 -sTCP:LISTEN
lsof -nP -iTCP:9001 -sTCP:LISTEN
```

启动 PostgreSQL 和 Redis：

```bash
brew services start postgresql
brew services start redis
```

可选安装 `yt-dlp` 和 `ffmpeg`：

```bash
brew install yt-dlp ffmpeg
which yt-dlp
which ffmpeg
```

如果 `which` 输出的是 `/opt/homebrew/bin/yt-dlp` 或 `/opt/homebrew/bin/ffmpeg`，可以在 `.env` 中使用：

```bash
VOFLOW_YTDLP_BIN="/opt/homebrew/bin/yt-dlp"
FFMPEG_WORKER="/opt/homebrew/bin/ffmpeg"
```

创建数据库用户和数据库，已存在时可以忽略对应错误：

```bash
psql -U "$(whoami)" -d postgres -c "CREATE USER voflow WITH PASSWORD 'voflow123' CREATEDB;"
psql -U "$(whoami)" -d postgres -c "CREATE DATABASE voflow OWNER voflow;"
```

启动 MinIO：

```bash
mkdir -p ~/minio-data
MINIO_ROOT_USER=voflow MINIO_ROOT_PASSWORD=voflow123 minio server ~/minio-data --console-address ":9001"
```

首次运行需要创建 bucket。安装过 `mc` 时可以执行：

```bash
mc alias set myminio http://localhost:9000 voflow voflow123
mc mb myminio/voflow --ignore-existing
mc anonymous set none myminio/voflow
```

如果没有安装 `mc`，可以打开 `http://localhost:9001`，使用 `voflow / voflow123` 登录后手动创建 bucket：`voflow`，并保持私有。

## 6. 初始化数据库

基础设施可连接后执行：

```bash
npm run db:generate
npm run db:migrate
npm run db:seed
```

命令含义：

- `db:generate`：生成 Prisma Client。
- `db:migrate`：执行开发迁移命令 `prisma migrate dev`，适合在本机交互式终端使用。
- `db:seed`：写入本地开发账号和基础团队数据。

如果在 CI、Codex、脚本任务等非交互环境中执行，`prisma migrate dev` 可能会报错：

```text
Prisma Migrate has detected that the environment is non-interactive
```

这时改用已有迁移的部署命令：

```bash
npx prisma migrate deploy
npm run db:seed
```

Seed 后可使用：

- 正常账号：`dev@voflow.local / dev123456`
- 禁用账号：`disabled@voflow.local / disabled123`

## 8. 运行验证

### 基础服务验证

```bash
pg_isready -h localhost -p 5432
redis-cli -h localhost -p 6379 ping
curl -fsS http://localhost:9000/minio/health/live
```

期望结果：

- PostgreSQL 返回 `accepting connections`
- Redis 返回 `PONG`
- MinIO health 接口返回成功

### 应用健康检查

```bash
curl -s http://localhost:3000/api/health
```

期望：

- `dependencies.postgres.status` 为 `up`
- `dependencies.redis.status` 为 `up`
- `dependencies.minio.status` 为 `up`
- 如果本地 AI 模型服务未启动，`models.*.status` 可以是 `offline`，不影响基础应用启动

### 素材上传依赖检查

素材库上传图片、音频、视频前，必须确认 MinIO 可达。上传接口会在写入对象前初始化 bucket；如果 MinIO 未启动，页面会收到 `STORAGE_ERROR / 存储初始化失败`。

```bash
docker compose ps minio
curl -fsS http://localhost:9000/minio/health/live
curl -s http://localhost:3000/api/health
```

期望：

- `docker compose ps minio` 中 `voflow-minio` 为 `Up` 或 `healthy`
- MinIO health 接口返回成功
- `/api/health` 中 `dependencies.minio.status` 为 `up`

如果只需要启动对象存储，可以执行：

```bash
docker compose up -d minio
```

### 公开参考链接导入检查

默认 `.env` 中 `VOFLOW_REFERENCE_LINK_IMPORT_ENABLED="false"`，此时真实公开链接导入会返回明确 fallback，不要求安装 `yt-dlp`。

需要本地验证真实导入时，先确认二进制可用：

```bash
yt-dlp --version
ffmpeg -version
```

然后在 `.env` 中启用：

```bash
VOFLOW_REFERENCE_LINK_IMPORT_ENABLED="true"
VOFLOW_YTDLP_BIN="yt-dlp"
VOFLOW_REFERENCE_ALLOWED_PLATFORMS="youtube,bilibili"
VOFLOW_REFERENCE_ALLOW_FULL_VIDEO_DOWNLOAD="false"
```

重启 `npm run dev` 后，在“爆款提取”页面粘贴 allowlist 内的公开链接。预期流程：

1. 先解析 metadata，只保存标题、平台、时长、封面、字幕信息。
2. 有字幕时推荐 `subtitle_only`，用户确认 reference-analysis-only 后进入字幕导入和结构分析。
3. 无字幕时可选择 `audio_extract`，用户确认 reference-analysis-only 后仅提取音频，不下载完整视频。
4. 平台不在 allowlist、超时、超长、完整视频/cookie/去水印/批量采集请求都会返回 fallback，用户应改用上传视频/音频或粘贴文案。

### 自动化测试

```bash
npm run test:run
```

该命令会运行 `tests/` 目录下的 Vitest 测试。

## 9. 常见问题

### 端口冲突

如果 `docker compose up -d` 失败，并提示 `5432`、`6379`、`9000` 或 `9001` 已占用，先查看占用进程：

```bash
lsof -nP -iTCP:5432 -sTCP:LISTEN
lsof -nP -iTCP:6379 -sTCP:LISTEN
lsof -nP -iTCP:9000 -sTCP:LISTEN
lsof -nP -iTCP:9001 -sTCP:LISTEN
```

本机服务已运行时，优先使用模式 B；想使用 Docker Compose 时，需要先停止本机冲突服务。

### 数据库连接失败

确认 `.env` 中的 `DATABASE_URL` 和实际 PostgreSQL 用户、密码、数据库一致：

```bash
psql "postgresql://voflow:voflow123@localhost:5432/voflow" -c "SELECT 1;"
```

如果用户或数据库不存在，重新执行：

```bash
psql -U "$(whoami)" -d postgres -c "CREATE USER voflow WITH PASSWORD 'voflow123' CREATEDB;"
psql -U "$(whoami)" -d postgres -c "CREATE DATABASE voflow OWNER voflow;"
```

### MinIO bucket 不存在

如果素材上传或健康检查依赖 MinIO 时报 bucket 相关错误，创建 `voflow` bucket：

```bash
mc alias set myminio http://localhost:9000 voflow voflow123
mc mb myminio/voflow --ignore-existing
mc anonymous set none myminio/voflow
```

### 素材上传提示存储初始化失败

如果上传素材库素材时接口返回：

```json
{
  "code": "STORAGE_ERROR",
  "message": "存储初始化失败"
}
```

优先检查 MinIO 是否启动并监听 `localhost:9000`：

```bash
lsof -nP -iTCP:9000 -sTCP:LISTEN
curl -fsS http://localhost:9000/minio/health/live
curl -s http://localhost:3000/api/health
```

如果 9000 没有监听，启动 MinIO：

```bash
docker compose up -d minio
```

如果 MinIO health 正常但上传仍失败，查看 `npm run dev` 控制台日志。上传接口会输出 MinIO 诊断信息，包括 `endpoint`、`port`、`bucket`、`useSSL` 和底层 `errorMessage`，用于判断是 `.env` 配置不一致、bucket 不可达还是连接被拒绝。

### 健康检查显示模型服务 offline

`.env` 中配置了本地 AI 模型服务：

- LLM：`http://localhost:8000`
- TTS：`http://localhost:5000`
- ASR：`http://localhost:6000`
- Avatar：`http://localhost:7000`

这些服务不是当前 Next.js 项目的启动脚本提供的。未启动时健康检查会显示 `offline`，属于可预期状态；只有涉及具体生成能力时才需要启动对应服务。

### 公开参考链接导入提示 yt-dlp 不可用

如果开启 `VOFLOW_REFERENCE_LINK_IMPORT_ENABLED="true"` 后，页面提示 `yt-dlp 不可用`，先确认当前运行 `npm run dev` 的终端能找到二进制：

```bash
which yt-dlp
yt-dlp --version
```

如果 `which yt-dlp` 没有输出，使用 Homebrew 安装：

```bash
brew install yt-dlp
```

如果 `yt-dlp` 已安装但 Next.js 进程找不到，改用绝对路径：

```bash
VOFLOW_YTDLP_BIN="/opt/homebrew/bin/yt-dlp"
```

修改 `.env` 后需要重启 `npm run dev`。

### 公开参考链接音频提取失败

音频提取依赖 `yt-dlp --extract-audio`，本机通常还需要 `ffmpeg` 完成转码或封装。如果 metadata 能解析，但 `audio_extract` 失败，先检查：

```bash
yt-dlp --version
ffmpeg -version
```

然后确认 `.env` 中没有关闭音频提取：

```bash
VOFLOW_REFERENCE_ALLOW_AUDIO_EXTRACT="true"
VOFLOW_REFERENCE_ALLOW_FULL_VIDEO_DOWNLOAD="false"
```

仍失败时，优先改用字幕导入或上传视频/音频。不要开启完整视频下载、cookie/登录态导入、去水印或批量采集。

### 国内平台参考链接只显示 fallback

当前页面可以识别抖音、快手、小红书、视频号、B站、YouTube、TikTok 等平台，但真实 `yt-dlp` 导入默认 allowlist 是：

```bash
VOFLOW_REFERENCE_ALLOWED_PLATFORMS="youtube,bilibili"
```

因此国内平台链接出现“不支持该参考链接平台”或“请上传视频/音频或粘贴文案”的 fallback 属于预期行为。MVP 不承诺对国内平台做自动提取，也不支持 cookie/登录态、去水印或批量采集。

## 10. 停止项目

如果使用 `npm run dev` 前台运行，按 `Ctrl+C` 停止 Web 应用。

如果使用 Docker Compose：

```bash
docker compose down
```

如果使用 Homebrew：

```bash
brew services stop postgresql
brew services stop redis
```

如果 MinIO 是前台运行，按 `Ctrl+C` 停止；如果是后台运行，先找到进程再停止：

```bash
lsof -nP -iTCP:9000 -sTCP:LISTEN
kill <PID>
```
