## 4. 当前正在做的能力

当前正在推进 `voflow-publish-assistant`：

- Task 0 已完成：确认平台规则、发布草稿、渠道账号、发布校验、Channel Adapter 和 API 响应必须进入公共 helper/service，不能散写在 API、Adapter 或 UI 中。
- Task 1 已完成：新增 `channel_accounts`、`publish_drafts`、`publishes` 数据表。
- Task 1 已完成：新增 `PublishPlatform`、`ChannelAccountStatus`、`PublishStatus` Prisma enum，收口发布平台、渠道账号状态和发布状态。
- Task 1 已完成：新增 schema 测试覆盖表、列、enum、外键、关键索引，并完成 RED/GREEN。
- Task 1 已完成：`prisma format`、`prisma validate`、`prisma migrate deploy`、`prisma generate`、publish schema test 和 export schema 回归测试均通过。
- Task 2 已完成：新增 `src/lib/publish/rules.ts`，集中配置 7 个发布平台的标题长度、标签数量、封面比例和视频时长限制。
- Task 2 已完成：新增 `tests/publish-platform-rules.test.ts`，覆盖平台顺序、规则完整性、关键平台边界值和未知平台错误，并完成 RED/GREEN。
- Task 3 已完成：新增本地 OpenAI-compatible 发布草稿 LLM provider，支持解析纯 JSON 和 fenced JSON。
- Task 3 已完成：新增 `generatePublishDrafts()` service，从 approved script 生成 title、description、tags、topics，并 upsert 到 `publish_drafts`。
- Task 3 已完成：新增 `POST /api/video-jobs/[jobId]/publish-drafts/generate`，支持鉴权、平台请求体验证、404 和发布草稿生成成功响应。
- Task 4 已完成：新增 `GET /api/video-jobs/[jobId]/publish-drafts`，支持按当前 team/job 查询平台草稿列表。
- Task 4 已完成：新增 `PUT /api/publish-drafts/[draftId]`，支持修改标题、描述、标签、话题和封面 artifact。
- Task 4 已完成：新增发布草稿 serializer/service，统一输出 tags/topics/rule/date 字段，保存时复用平台规则校验标题长度、标签数量，并校验封面 artifact 属于同一个 job 且类型为 `cover`。
- Task 5 已完成：新增 `GET /api/channel-accounts`，返回所有发布平台的账号授权展示状态。
- Task 5 已完成：新增渠道账号 serializer/service，支持 connected、expired、not_connected 展示口径，返回账号昵称和过期时间，过期 token 自动展示为 expired。
- Task 5 已完成：新增 AES-256-GCM 渠道 token 加密 helper 和 `saveChannelAccountToken()`，并在 `.env.example` 增加 `CHANNEL_TOKEN_ENCRYPTION_SECRET` 示例。
- Task 6 已完成：新增 `GET /api/channel-accounts/[platform]/authorize`，返回 mock OAuth 授权/重新授权入口。
- Task 6 已完成：新增 `POST /api/channel-accounts/[platform]/mock-authorize`，复用 token 加密 helper 创建或覆盖 connected mock channel account。
- Task 6 已完成：新增 OAuth mock provider 公共模块和 `ChannelOAuthAdapter` 接口占位，明确真实平台 OAuth 和发布 Channel Adapter 尚未实现。
- Task 7 已完成：新增 `POST /api/video-jobs/[jobId]/publish/validate`，支持按平台执行发布前检查。
- Task 7 已完成：新增发布检查公共类型和 `validatePublishParameters()` service，校验标题长度、标签数量、封面比例、最终视频是否存在、视频比例、视频时长和 channel account 状态。
- Task 7 已完成：检查结果会写回 `publish_drafts.validationJson`，失败时返回 `PUBLISH_VALIDATION_FAILED` 和逐项原因。
- Task 8 已完成：新增 `PublishChannelAdapter` 接口，包含 `uploadVideo()`、`publish()`、`getStatus()`、`retry()`。
- Task 8 已完成：新增 mock channel adapter，返回稳定的 mock request id、remote video id、remote publish id 和 published 状态。
- Task 8 已完成：新增 Adapter 错误码和结果类型，为 Task 9 一键发布 API、Task 10 失败重试 API 复用；当前不代表真实平台发布能力。

## 7. 建议下一步

下一步应继续执行：

```text
voflow-publish-assistant Task 9: 实现一键发布 API
```

建议启动顺序：

1. 实现 `POST /api/video-jobs/[jobId]/publish`，只对检查通过且 connected 的平台创建发布记录。
2. expired 或 not_connected 平台应标记 skipped，并保存稳定失败原因，不能调用 adapter。
3. 已通过平台应复用 `getChannelAdapter()` 调用 mock adapter，保存 request id、remote id 和平台结果。
4. 不在 Task 9 中实现失败重试 API 或发布 UI。
5. 执行 focused publish API tests，并根据改动范围运行 lint/build 或等价验证命令。
