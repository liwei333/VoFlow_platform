## 4. 当前正在做的能力

刚完成的 `voflow-video-render` 能力包括：

- 创建 `avatar_render_requests` 数据模型，关联 job、node、avatar、audio artifact。
- 定义 Avatar Render Provider 接口，并提供 mock MP4 provider 和 local provider adapter。
- 校验 avatar ready、授权通过、TTS audio artifact 存在、项目画面比例一致。
- 提供低清预览渲染 API。
- 接入 `avatar_render` Worker，下载 source image/audio，调用 provider，上传 `avatar_video` artifact。
- 使用 ffprobe 校验输出视频大小、duration 和 video stream。
- 支持预览确认、重新预览、高清渲染任务创建。
- 从 `local_model_services.avatar` 读取真实模型服务配置，不直接散写 `AVATAR_BASE_URL`。
- 实现数字人渲染 UI：选择我的数字人、选择已确认 TTS 音频、裁剪、低清预览、确认预览、重新预览。
- 新增 acceptance/UI/schema/service/API/worker/provider/output-validation 等测试覆盖。

当前剩余复验点：

- 真实 MuseTalk/SadTalker 或等价本地数字人渲染服务仍需最终环境人工复验。
- `voflow-video-render` 在 MVP 主线状态中仍保持 `partial`，原因是不能把 mock/provider 输出标记为真实模型生产能力。
- `voflow-workflow-engine` 仍需要跟随后续 advanced editing、export、publish 节点继续端到端联调。

## 6. 风险和待复验点

当前进度里的主要风险不是任务数量，而是真实环境复验和成片闭环尚未完成：

- `voflow-voice-clone` 虽然 tasks 已 12/12 完成，但真实 GPT-SoVITS/CosyVoice trainer 没有在 checkpoint 人工联调，因此 plan 仍标为 `partial`。
- `voflow-video-render` 依赖真实 MuseTalk/SadTalker 或等价本地 avatar 服务。mock/provider 流程和自动化测试已经覆盖，但真实模型服务仍需最终环境复验。
- `voflow-workflow-engine` 的基础任务已完成，但任务中心必须继续和 reference_url_import、voice_clone、avatar_render、export、publish 节点做端到端联调，因此仍是 `partial`。
- `voflow-advanced-editing` 仅完成底层配置表；配置查询/保存、授权校验、预览 Worker 和 UI 尚未实现，`voflow-packaging-export`、`voflow-publish-assistant` 也尚未启动，完整“高级剪辑 -> 成片下载 -> 多平台发布”闭环还没有打通。
- plan 要求进入下一个 Spec 前必须确认当前 Spec 相关测试、lint、build、MVP 状态矩阵和 checkpoint 记录同步完成。
