# 智能口播平台需求文档

版本：v0.1
日期：2026-06-19
项目代号：VoFlow Platform
参考目标：类似“齐博士口播智能体”的全自动化 AI 口播视频生产与发布平台

## 1. 项目背景

短视频口播账号的生产链路通常包含选题、对标拆解、文案仿写、配音、数字人口播、字幕、封面、标题、发布和复盘。传统流程依赖多种工具和人工剪辑，交付慢、质量不稳定、批量能力弱。

VoFlow Platform 的目标是把这些步骤封装为一个可控的 AI 工作流平台，让运营人员通过“输入主题/链接/文案 -> 审核关键节点 -> 生成口播视频 -> 多平台发布”的方式完成内容生产。

## 2. 产品目标

### 2.1 一期目标

跑通从文案到成片的最小闭环：

1. 支持用户输入主题、文案或参考视频链接。
2. 支持文案提取、结构化分析和口播化改写。
3. 支持本地大模型生成口播文案、标题和风险提示，默认不依赖线上大模型 API。
4. 支持 AI 法务审查、风险替换建议和人工确认。
5. 支持预置音色和用户声音克隆。
6. 支持基于图片或预置形象生成数字人口播视频。
7. 支持自动字幕、BGM、画中画、标题和封面生成。
8. 支持视频下载、任务历史查看和多平台发布辅助。
9. 支持本地部署，MVP 可以在单机或局域网服务器运行。

### 2.2 二期目标

把单视频生产升级为可规模化运营工具：

1. 支持用户自助声音克隆和音色管理。
2. 支持批量选题、批量文案、批量成片。
3. 支持多模板字幕、封面和画面布局。
4. 支持团队协作、审核流和素材资产库。
5. 支持抖音、快手、小红书、视频号、YouTube Shorts 等渠道发布适配。

### 2.3 三期目标

形成商业化闭环：

1. 支持套餐计费、用量计费和企业空间。
2. 支持内容数据回流、发布效果分析和选题优化。
3. 支持专属数字人、专属音色、品牌语气库和行业模板库。
4. 支持 API/OpenAPI，把视频生成能力开放给第三方系统。

## 3. 用户角色

| 角色 | 主要诉求 | 关键权限 |
| --- | --- | --- |
| 内容运营 | 快速批量产出口播视频 | 创建项目、生成视频、编辑文案、下载/发布 |
| 团队主管 | 控制内容质量和发布节奏 | 审核视频、管理模板、查看报表 |
| 企业管理员 | 管理账号、额度、合规资产 | 用户管理、套餐管理、素材权限、审计日志 |
| 平台运营 | 维护模型、模板、渠道能力 | 模型配置、渠道配置、任务监控、失败处理 |

## 4. 核心业务流程

```mermaid
flowchart LR
    A["输入主题/文案/参考链接"] --> B["文案提取与分析"]
    B --> C["文案仿写与口播化"]
    C --> D["选择音色并生成语音"]
    D --> E["选择数字人并生成口播视频"]
    E --> F["字幕、BGM、封面、标题"]
    F --> G["预览与人工微调"]
    G --> H["导出或发布"]
    H --> I["任务记录与数据复盘"]
```

## 5. 功能需求

### 5.1 账号与工作台

用户可以注册、登录、进入工作台，查看项目、任务、素材和发布记录。

功能点：

1. 支持手机号、邮箱或第三方账号登录。
2. 支持个人空间和团队空间。
3. 支持角色权限：成员、审核员、管理员。
4. 支持用量统计：生成时长、TTS 字数、数字人渲染次数、发布次数。

验收标准：

1. 用户登录后只能访问自己或所属团队的项目。
2. 管理员可以禁用用户、调整角色、查看用量。
3. 所有生成和发布行为进入审计日志。

### 5.2 项目与素材管理

项目用于承载一次或一组视频生产任务，素材库用于复用文案、音色、数字人、背景图、BGM 和封面模板。

功能点：

1. 新建项目：选择视频比例、目标平台、内容行业和默认模板。
2. 素材上传：图片、音频、视频、字幕、字体、BGM。
3. 素材标签：行业、风格、用途、授权状态。
4. 素材权限：个人可见、团队可见、平台公共。

验收标准：

1. 支持 9:16、16:9、1:1 三种基础画布比例。
2. 素材必须记录来源、上传人、授权说明和使用记录。
3. 未授权素材不能进入发布流程。

### 5.3 对标内容输入与文案提取

用户可以输入主题、粘贴文案、上传视频/音频，或填写参考链接。平台把输入内容转为可编辑文案。

功能点：

1. 文案粘贴：直接进入文案编辑器。
2. 音视频上传：通过 ASR 转写为文案。
3. 参考链接：优先要求用户确认拥有处理权；支持解析失败后引导用户手动上传。
4. 文案结构化：提取主题、观点、卖点、情绪、受众、禁用词。

验收标准：

1. 上传 3 分钟以内视频可生成带时间戳的转写文本。
2. 转写结果支持人工编辑和版本保存。
3. 参考链接解析失败时，用户可以切换到手动上传，不中断任务。

### 5.4 文案仿写与口播化

平台基于原文生成多版口播稿，用户可以选择风格、长度、语气和目标平台。MVP 默认调用本地部署的大模型服务生成文案和标题；只有管理员显式配置外部模型服务时，系统才允许调用线上大模型 API。

功能点：

1. 支持生成 3-5 个候选文案。
2. 支持风格：科普、种草、测评、观点、情绪共鸣、直播切片风格。
3. 支持长度：15 秒、30 秒、60 秒、90 秒、3 分钟。
4. 支持原创度检查、敏感词检查和事实风险提示。
5. 支持品牌语气库：常用开场、结尾、禁用词、行业术语。
6. 支持配置本地大模型地址、模型名称、上下文长度、超时时间和最大输出 token。
7. 支持本地大模型健康检查，模型不可用时任务失败并允许重试。

验收标准：

1. 每次生成必须保留原始输入、提示词参数、模型版本和输出版本。
2. 用户可以回滚到历史文案版本。
3. 文案进入视频生成前必须通过敏感词和授权确认。
4. 默认配置下，文案内容不得发送到外部线上大模型服务。
5. 本地大模型不可用时，系统必须返回明确错误并停留在文案节点，不得继续生成 TTS。

### 5.5 语音合成与声音克隆

当前原型对齐版本同时支持预置音色和基础声音克隆。声音克隆需要上传授权音频样本，完成授权确认后通过本地 TTS/声音克隆服务生成专属音色；后续阶段再增强质量评估、批量训练和企业音色库。

功能点：

1. 预置音色：男声、女声、沉稳、活泼、专业、情绪化等。
2. TTS 参数：语速、音调、停顿、情绪、音量。
3. 声音克隆：上传授权音频，完成身份验证后生成专属音色。
4. 音色版本管理：每次训练和配置变更生成版本。

验收标准：

1. 一期支持 3000 字以内文案生成语音。
2. 语音生成失败时可重试，不重复扣费。
3. 声音克隆必须记录授权声明、验证材料和使用范围。

### 5.6 数字人口播生成

用户选择预置数字人，或拍照/上传本人照片制作专属 AI 数字人。平台根据语音驱动数字人口型，生成可用于口播的短视频。

功能点：

1. 形象来源：平台预置、用户上传、企业专属。
2. 生成模式：快速预览、高清生成。
3. 画面布局：半身口播、头像口播、画中画、背景图/视频。
4. 支持数字人、字幕、背景、素材图层的组合。
5. 支持用户拍照或上传照片创建“我的数字人”。
6. 支持照片质量检测：单人正脸、无遮挡、光线充足、清晰度、分辨率、人脸角度。
7. 支持数字人资产管理：命名、预览、删除、设为默认、授权状态查看。
8. 支持同一个数字人复用于多条口播视频，不需要每次重新上传照片。

用户上传照片制作数字人流程：

```mermaid
flowchart LR
    A["拍照/上传本人照片"] --> B["照片质量检测"]
    B --> C["肖像授权确认"]
    C --> D["生成数字人预览"]
    D --> E["用户确认入库"]
    E --> F["选择文案和音色"]
    F --> G["生成口播视频"]
```

验收标准：

1. 快速预览用于低清确认，高清生成用于最终导出。
2. 用户上传形象必须确认肖像授权，授权记录必须和数字人资产绑定。
3. 渲染任务可以暂停、重试、取消，并展示进度。
4. 不符合质量要求的照片不能进入数字人生成流程，并给出具体原因。
5. 用户创建的数字人必须出现在“我的数字人”列表，并可在后续视频任务中选择。
6. 删除数字人后，不能再用于新任务；历史已生成视频和审计记录保留。

### 5.7 字幕、BGM、标题和封面

平台基于最终音频和文案自动生成视频包装元素。

功能点：

1. 字幕：自动分句、时间轴对齐、字体样式、关键词高亮。
2. BGM：按情绪、行业和节奏推荐，支持自动闪避混音。
3. 标题：生成多平台标题和话题标签。
4. 封面：自动选帧、模板合成、标题图层编辑。

验收标准：

1. 字幕导出支持硬字幕 MP4 和 SRT/ASS 文件。
2. BGM 音量不能盖过人声，默认做人声优先混音。
3. 封面尺寸跟随目标平台生成。

### 5.8 多平台发布

用户授权渠道账号后，可以发布视频或创建待发布草稿。

功能点：

1. 渠道账号 OAuth 授权。
2. 渠道适配器：抖音、快手、小红书、视频号、YouTube Shorts、TikTok。
3. 支持标题、正文、标签、封面、定时发布时间。
4. 支持发布前审核、发布失败重试、状态同步。

验收标准：

1. 每个平台的发布参数必须独立校验。
2. 发布失败要保留错误码、请求 ID 和重试记录。
3. 用户可以查看每条视频的渠道发布状态。

### 5.9 任务中心与工作流

平台把每一次生成拆成可观测的异步任务。

功能点：

1. 工作流节点：输入解析、文案生成、TTS、数字人、字幕、混音、封面、发布。
2. 每个节点支持状态：等待、运行、成功、失败、已取消、待人工确认。
3. 支持断点续跑：某个节点失败后，只重跑该节点和下游节点。
4. 支持人工打点：文案确认、语音确认、视频确认、发布确认。

验收标准：

1. 前端可以实时看到任务进度和当前节点。
2. 失败节点展示可读错误原因和下一步操作。
3. 重试不能覆盖原始结果，必须生成新版本。

## 6. 非功能需求

### 6.1 性能

| 场景 | 一期目标 |
| --- | --- |
| 1 分钟文案改写 | 30 秒内返回候选 |
| 1 分钟 TTS | 60 秒内完成 |
| 1 分钟低清数字人预览 | 5 分钟内完成 |
| 1 分钟高清视频生成 | 15 分钟内完成 |
| 工作台页面打开 | 3 秒内可交互 |

### 6.2 稳定性

1. 异步任务必须支持重试、超时、取消和幂等。
2. 模型服务异常不能影响 API 主服务登录、项目查看等基础能力。
3. 所有产物必须落对象存储，不能只保存在本地临时目录。
4. 本地大模型服务异常时，只影响文案改写、标题生成和风险提示节点，不影响项目、素材、任务查询。

### 6.2.1 本地部署

1. MVP 必须支持本地 Docker Compose 或等价方式部署 Web、API、PostgreSQL、Redis、MinIO、Worker 和本地模型服务。
2. MVP 默认不要求公网访问，不要求调用线上大模型。
3. 本地部署必须支持配置 GPU/CPU 模式；GPU 用于本地大模型、TTS、数字人和视频生成加速。
4. 本地部署必须提供模型服务健康检查，便于判断本地大模型是否加载成功。

### 6.3 安全与合规

1. 声音克隆和肖像驱动必须要求用户确认授权。
2. 平台必须保留授权记录、素材来源、生成日志和发布日志。
3. 支持敏感词、版权风险、AI 生成标识和人工审核。
4. 渠道 token 必须加密存储，支持用户主动解绑。

### 6.4 成本控制

1. 数字人渲染是主要 GPU 成本，必须区分快速预览和高清生成。
2. 批量任务需要排队和并发限额。
3. 每个工作流节点记录耗时、资源、失败率和费用估算。

## 7. MVP 范围

### 7.1 必做

1. 登录和个人工作台。
2. 项目创建和单视频任务。
3. 爆款链接导入、平台识别、上传音视频转写和爆款结构提取。
4. 使用本地大模型完成文案改写、标题生成和发布文案生成。
5. AI 法务审查、风险替换建议、逐条确认和忽略原因记录。
6. 预置音色 TTS 和用户声音克隆。
7. 拍照/上传本人照片创建数字人，并驱动单数字人口播视频。
8. 字幕硬烧录、BGM 混音、画中画、背景素材和剪辑预览。
9. 封面生成、发布标签、描述、话题和平台参数检查。
10. 多平台账号授权状态、一键发布、部分成功、失败重试和发布日志。
11. 视频下载。
12. 任务中心、失败重试、基础日志。

### 7.2 暂不做

1. 企业团队审核流。
2. 复杂封面编辑器。
3. 计费系统。
4. 数据复盘和选题推荐。
5. 发布后评论私信运营。

### 7.3 建议验收 Demo

用户粘贴爆款视频链接或上传参考视频，系统提取文案和爆款结构；系统用本地大模型生成改写文案，并完成 AI 法务审查和风险替换确认。用户上传声音样本生成克隆音色，上传本人正脸照片生成“我的数字人”。随后系统完成配音、数字人口播、字幕、BGM、画中画、封面、发布信息生成，最终导出一个 9:16 MP4 文件，并支持一键发布到已授权平台。

## 9. 关键风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 开源模型许可证限制 | 影响商业化 | 选型阶段做许可证清单，商业化前法律复核 |
| 数字人画质不稳定 | 影响用户体验 | 先做低清预览，高清生成提供参数和模板约束 |
| GPU 成本过高 | 影响毛利 | 任务排队、预览/高清分层、动态批处理、缓存 |
| 平台发布 API 限制 | 影响自动发布 | MVP 先下载，二期再做渠道授权和适配 |
| 声音/肖像侵权 | 法务风险 | 授权验证、合规声明、审计日志、人工审核 |

## 10. 成功指标

1. 新用户 10 分钟内完成第一条视频生成。
2. 单条 1 分钟口播视频的人工操作时间小于 5 分钟。
3. MVP 任务成功率大于 85%。
4. 生成任务失败后，80% 以上可通过重试恢复。
5. 单条视频生成成本可被准确拆分到 ASR、LLM、TTS、数字人、合成和存储。
